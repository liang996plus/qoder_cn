> 状态：草稿（已根据审核反馈修订）

---

## 1. 项目概述

### 1.1 背景与目标

基于现有 hiagent 辅助 Web 服务和已放置的 Excel 模板文件（`app/templates/分期限目标检视.xlsx`），新增一个 API 接口，接收当前日期和结构化 JSON 数组数据，将数据填充到模板中，动态替换列头日期后生成 Excel 文件并返回下载链接。

### 1.2 核心价值

- 自动化填充固定格式的检视报表，避免人工手动编辑 Excel
- 列头日期根据当前日期自动计算，无需手动修改
- 总计行自动汇总，减少出错风险

## 2. 功能需求

### 2.1 接口定义

| 项目 | 说明 |
|------|------|
| 方法 | POST |
| 路径 | `/api/v1/report/term-target-review` |
| 内容类型 | application/json |
| 响应格式 | application/json（成功返回文件下载链接） |

### 2.2 请求数据模型

```json
{
  "current_date": "2026-06-22",
  "rows": [
    {
      "product_type": "固定收益类",
      "term_category": "超短期固收【T+1日开】",
      "daily_scale": 1200.50,
      "vs_last_month": -50.30,
      "sales_analysis": "净增长 +120.50 万元，主要产品：A、B"
    },
    {
      "product_type": "固定收益类",
      "term_category": "超短期固收【7D-2M】",
      "daily_scale": 800.00,
      "vs_last_month": 30.20,
      "sales_analysis": "净增长 -80.00 万元，主要产品：C"
    },
    {
      "product_type": "固定收益类",
      "term_category": "中短期固收",
      "daily_scale": 500.00,
      "vs_last_month": 10.00,
      "sales_analysis": "无数据"
    },
    {
      "product_type": "固定收益类",
      "term_category": "长期限固收",
      "daily_scale": 300.00,
      "vs_last_month": -5.00,
      "sales_analysis": "净增长 +50.00 万元，主要产品：D"
    },
    {
      "product_type": "含权益类",
      "term_category": "含权益类",
      "daily_scale": 200.00,
      "vs_last_month": 15.00,
      "sales_analysis": "净增长 +30.00 万元，主要产品：E"
    }
  ]
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current_date | string | 是 | 当前日期，ISO 格式 `YYYY-MM-DD` |
| rows | array | 是 | 数据行数组，按固定顺序排列，至少 1 行 |
| rows[].product_type | string | 是 | 产品类型（如"固定收益类"、"含权益类"） |
| rows[].term_category | string | 否 | 期限分类，总计行可为空 |
| rows[].daily_scale | number | 是 | 当日规模，保留两位小数 |
| rows[].vs_last_month | number | 是 | 较上月末变化，保留两位小数 |
| rows[].sales_analysis | string | 是 | 销量分析文本，格式如"净增长 ±XXX.XX 万元，主要产品：A、B"；无数据填"无数据" |

**固定顺序（5 个元素）：**

| 序号 | 产品类型 | 期限分类 |
|------|----------|----------|
| 1 | 固定收益类 | 超短期固收【T+1日开】 |
| 2 | 固定收益类 | 超短期固收【7D-2M】 |
| 3 | 固定收益类 | 中短期固收 |
| 4 | 固定收益类 | 长期限固收 |
| 5 | 含权益类 | 含权益类 |

### 2.3 Excel 模板结构

模板文件：`app/templates/分期限目标检视.xlsx`（6 列 A-F，11 行）

#### 2.3.1 合并单元格布局

| 行 | 列范围 | 内容 | 说明 |
|----|--------|------|------|
| 1 | A1:F1 | 二、分期限目标检视 | 标题行，6列合并 |
| 2-3 | A2:A3 | 产品类型 | 纵向合并 |
| 2-3 | B2:B3 | 期限分类 | 纵向合并 |
| 2 | C2:D2 | **{month}月规模** | 动态月份 |
| 2 | E2:F2 | 销量分析 | — |
| 3 | E3:F3 | **主要产品销量情况（{start}-{end}）（{n}个工作日）** | 动态周期 |
| 4-7 | A4:A7 | 固定收益类 | 4行纵向合并 |
| 8 | A8, B8 | 含权益类 | 单行 |
| 9 | A9:B9 | 总计 | 合计行 |
| 9 | E9:F9 | "-" | 销量分析固定值 |

> 注：模板总行数为 9 行（3行表头 + 4行固定收益 + 1行含权益 + 1行总计）。

#### 2.3.2 数据行与 JSON 元素的映射（按索引一一对应）

| JSON 索引 | 模板行 | 期限分类 | 合并说明 |
|-----------|--------|----------|----------|
| rows[0] | 第 4 行 | 超短期固收【T+1日开】 | 单行 |
| rows[1] | 第 5 行 | 超短期固收【7D-2M】 | 单行 |
| rows[2] | 第 6 行 | 中短期固收 | 单行 |
| rows[3] | 第 7 行 | 长期限固收 | 单行 |
| rows[4] | 第 8 行 | 含权益类 | 单行 |
| — | 第 9 行 | 总计（自动计算） | 合计行 |

> **索引制映射**：rows[0-3] 对应固定收益类 4 个子类（第 4-7 行），rows[4] 对应含权益类（第 8 行）。
>
> 若 rows 不足 5 行，仅填充已有索引对应的行，其余行保持模板原样（空），不得跳行填充。
>
> 示例：传入 3 个元素 → 填充第 4、5、6 行，第 7、8 行留空。

#### 2.3.3 数值列

| 列 | 数据内容 | 格式 |
|----|----------|------|
| C | daily_scale（当日规模） | 数值，保留2位小数 |
| D | vs_last_month（较上月末） | 数值，保留2位小数 |
| E | sales_analysis（销量分析） | 文本 |

### 2.4 动态日期计算规则

根据请求参数 `current_date` 自动计算以下动态内容：

| 模板位置 | 动态内容 | 计算方式 | 示例（current_date=2026-06-22） |
|----------|----------|----------|------|
| C2 | `{month}月规模` | `current_date.month` | `6月规模` |
| C3 | `{date}规模` | `M/D` 格式（月/日，不补零） | `6/22规模` |
| E3 | `主要产品销量情况（{start}-{end}）（{n}个工作日）` | 见下方计算 | `主要产品销量情况（6/16-6/22）（5个工作日）` |

**E3 周期计算逻辑（往前推一周）：**

1. **起始日（start）**：`current_date - 6天`（含当天共7天）
   - `start = current_date - timedelta(days=6)`
2. **结束日（end）**：`current_date`
3. **工作日数（n）**：start 到 end（含）之间周一至周五的天数

> 示例：current_date = 2026-06-22（周一），start = 6/16（周二），end = 6/22，工作日 = 5天（周二~周一）

### 2.5 总计行计算规则

第 9 行（合计行）自动计算：

| 列 | 计算方式 |
|----|----------|
| A | "总计" |
| B | "总计"（与A列合并 A9:B9） |
| C | `sum(row.daily_scale for row in rows)`（仅对已提供的行求和） |
| D | `sum(row.vs_last_month for row in rows)`（仅对已提供的行求和） |
| E | "-"（固定文本，E9:F9 合并） |

### 2.6 响应数据模型

成功响应（HTTP 200）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "filename": "report_term_target_review_a1b2c3d4.xlsx",
    "format": "xlsx",
    "download_url": "/api/v1/file/download/report_term_target_review_a1b2c3d4.xlsx",
    "row_count": 5,
    "column_count": 6
  },
  "request_id": "..."
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| filename | string | 生成的文件名 |
| format | string | 固定为 "xlsx" |
| download_url | string | 文件下载路径（复用现有 `/api/v1/file/download/{filename}`） |
| row_count | int | 数据行数（不含表头和合计行） |
| column_count | int | 固定为 6 |

### 2.7 错误处理

| HTTP 状态码 | 场景 | 说明 |
|-------------|------|------|
| 422 | 参数校验失败 | Pydantic 自动校验，返回字段级错误详情 |
| 400 | 报表生成失败 | openpyxl 写入异常等，code=4003 |

## 3. 非功能需求

- **响应时间**：< 5 秒
- **文件管理**：复用现有 `file_manager`（save_file / periodic_cleanup）
- **统一响应**：使用 `ApiResponse` 统一格式
- **错误码**：复用已有 `REPORT_GENERATION_FAILED = 4003`
- **API 路径**：kebab-case 命名规范
- **数值精度**：所有金额字段保留 2 位小数

## 4. 用户故事

### US-001：生成标准检视报表

- **角色**：作为 API 调用方
- **需求**：我希望传入当前日期和 5 行产品数据
- **价值**：以便自动生成格式完整的分期限目标检视 Excel 报表

- **角色**：作为 API 调用方
- **需求**：我希望列头中的月份、日期、周周期自动根据当前日期计算
- **价值**：以便每次生成的报表日期准确，无需手动修改
- **优先级**：P0

### US-003：总计行自动汇总

- **角色**：作为 API 调用方

- **价值**：以便减少人工计算和录入错误
- **优先级**：P0

## 5. 验收标准

### AC-001：基本生成（US-001）

- [ ] POST /api/v1/report/term-target-review 返回 200 和文件下载链接
- [ ] 下载的 xlsx 文件可被 Excel/WPS 正常打开
- [ ] Excel 共 6 列（A-F）、9 行（3行表头 + 4行固定收益 + 1行含权益 + 1行总计 = 9行）
- [ ] 合并单元格结构与修正后模板一致
- [ ] 5 个 JSON 元素按索引顺序正确填入第 4-7 行（固定收益）和第 8 行（含权益）

### AC-002：动态日期（US-002）

- [ ] C2 显示正确的月份（如 current_date=2026-06-22 → "6月规模"）
- [ ] C3 显示正确的日期（如 "6/22规模"）
- [ ] E3 显示往前推一周的周期（6/16-6/22）和正确的工作日天数（5天）
- [ ] 不同月份/日期的输入生成不同的列头文本

### AC-003：总计行（US-003）

- [ ] C9 = 所有已提供 rows 的 daily_scale 之和
- [ ] D9 = 所有已提供 rows 的 vs_last_month 之和
- [ ] E9 = "-"（固定文本）
- [ ] A9:B9 合并显示"总计"

### AC-004：数值精度

- [ ] daily_scale 和 vs_last_month 保留 2 位小数
- [ ] 负数正确显示（如 -50.30）

### AC-005：参数校验与部分填充

- [ ] 缺少 current_date → 422
- [ ] 缺少 rows → 422
- [ ] rows 为空数组 → 422
- [ ] current_date 格式非法 → 422
- [ ] rows 仅 3 个元素时，填充第 4、5、6 行，第 7、8 行保持模板原样
- [ ] rows 不足 5 行时，总计行仅对已提供的行求和
- [ ] 不允许跳行填充（如只提供 rows[0] 和 rows[3]，中间 rows[1]/rows[2] 对应行留空）

## 6. 技术实现要点

| 项目 | 方案 |
|------|------|
| 模板加载 | openpyxl 加载 `app/templates/分期限目标检视.xlsx` |
| 数据填充 | 在模板副本上修改单元格值，保留原有合并单元格和样式 |
| 合并单元格写入 | 对合并区域写入起始单元格坐标即可 |
| 日期计算 | Python `datetime` 模块，`weekday()` 获取周几 |
| 文件保存 | 复用 `file_manager.save_file()`，返回 bytes |
| 文件下载 | 复用 `/api/v1/file/download/{filename}` |
