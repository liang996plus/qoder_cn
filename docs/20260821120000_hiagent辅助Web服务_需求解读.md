## 🎯 一句话总结

这个系统是 AI Agent 的"万能后厨"——Agent 只管点菜（提出分析需求），后厨自动完成买菜、做菜、摆盘（获取数据、处理分析、生成图表报告），然后把成品端上桌。

---

## 📖 故事化背景

想象你是一个公司里的 AI 助手（我们叫它 hiagent），老板经常给你布置各种分析任务：

- "帮我分析一下这几个基金产品哪个收益最好，给我出个排名图表！"（竞品分析）
- "看看最近哪些机构在大量买入，画出他们的行为画像！"（机构行为分析）
- "这个产品最近规模涨了多少？帮我做个趋势预测！"（产品规模增量分析）

问题来了：每种分析，数据来源不一样（有的从数据库取，有的从外部 API 拉），处理逻辑不一样（有的要统计，有的要清洗），输出格式也不一样（有的要图表，有的要 PDF 报告）。

如果每个场景都从头写一套代码，那每新增一种分析就得重新造轮子，费时费力还容易出错。

所以，团队决定建一个"通用后厨"——不管来什么分析需求，只要写一份"菜谱"（场景配置），后厨就能自动走完"买菜→洗菜→切菜→炒菜→装盘"的全流程。这样新增一种分析场景，只需要写一份新的菜谱就行了，不用动后厨的设备。

## 🏠 生活类比

### 类比一：自助餐厅

把这个系统想象成一家自助餐厅：

- **顾客（AI Agent）**：走进餐厅，说"我要一份竞品分析套餐"
- **菜谱（YAML 场景配置）**：写好了每道套餐需要什么食材、怎么烹饪、怎么摆盘
- **采购部（连接器 Connector）**：根据菜谱去不同的地方采购食材——有的从菜市场（数据库），有的从进口超市（外部 API），有的从顾客自带的食材（上传文件）
- **后厨流水线（Pipeline Engine）**：食材到了以后，按顺序经过洗菜工→切菜工→炒锅→装盘，每一步做完传给下一步
- **出品台（输出组装器）**：最终把做好的菜品（图表、表格、报告、文件）整整齐齐端给顾客

### 类比二：乐高积木

原子 API 就像一盒乐高积木——每块积木是一个小功能（查数据、画图表、转格式）。你可以自由组合这些积木，拼出任何你想要的东西。Pipeline 模式则是已经拼好的成品套装，一键开箱即用。

## 🧩 功能模块拆解

### 数据处理模块（`/api/v1/data`）

**一句话说清楚**：把乱七八糟的原始数据变成干净、整齐、可以直接用的表格。

**举个例子**：老板丢来一份 Excel 表格，里面有些单元格是空的，有些日期格式不对，有些数字带了百分号。这个模块会自动识别文件格式，把空值处理掉，把格式统一，然后帮你做筛选、排序、统计等操作——就像有个助理帮你把一堆乱糟糟的数据整理得井井有条。

**涉及的专业术语**：
- **CSV/Excel/JSON**：三种常见的数据文件格式，分别是逗号分隔的文本、Excel 表格、结构化文本
- **编码检测**：自动识别文件是用什么"语言"（字符编码）写的，防止中文变乱码
- **聚合**：把数据按某个维度汇总，比如"按月份统计总销售额"
- **透视**：把数据换个角度看，比如从"按日期列数据"变成"按产品列数据"
- **DuckDB**：一个轻量级的数据库引擎，处理表格数据特别快

---

### 可视化与渲染模块（`/api/v1/visual`）

**一句话说清楚**：把枯燥的数字变成好看的图表和报告。

**举个例子**：数据处理完之后，你得到一张大表格。这个模块能把表格变成柱状图、折线图、饼图等各种图表，还能生成一份排版精美的 HTML 报告——就像有个设计师帮你把数据做成了 PPT。

**涉及的专业术语**：
- **matplotlib/plotly**：两个 Python 画图工具库，matplotlib 画静态图，plotly 画可交互的动态图
- **PNG/SVG/HTML**：三种图片/页面格式。PNG 是普通图片，SVG 是可以放大不模糊的矢量图，HTML 是网页
- **Jinja2 模板**：一种"填空题"工具，把数据自动填入预设的报告模板里
- **Markdown 转 HTML**：把简单的纯文本格式标记转换成漂亮的网页

---

### 文件与文档操作模块（`/api/v1/file`）

**一句话说清楚**：帮你转换文件格式、生成各种文档、管理临时文件。

**举个例子**：你分析完了数据，需要把结果导出成 Excel 给财务看、生成 PDF 给领导签字、打包成 ZIP 发给客户。这个模块全都能做。而且它会自动清理 2 小时前的临时文件，不用担心硬盘被塞满——就像有个文件管家帮你打理一切。

**涉及的专业术语**：
- **格式互转**：把一种文件格式变成另一种，比如 CSV 转 Excel、JSON 转 HTML
- **流式下载**：文件一边生成一边下载，不用等整个文件都做好了才能开始下，大文件特别有用
- **临时文件管理**：系统生成的中间文件会在 2 小时后自动删除，防止占用空间

---

### API 编排模块（`/api/v1/proxy`）

**一句话说清楚**：帮 AI Agent 代替它去调用外面的服务，还能自动处理各种麻烦事。

**举个例子**：AI 需要从一个外部网站拉数据，但这个网站有时候很慢、有时候会拒绝请求。这个模块就像个靠谱的跑腿小哥——帮你去调接口，失败了自动重试，请求太多就自动排队，还能把对方返回的格式转成你想要的格式。你只管下命令，跑腿的活儿它全包了。

**涉及的专业术语**：
- **HTTP 代理**：帮你转发网络请求，就像帮你寄快递的中转站
- **并发请求**：同时发出多个请求，不用排队一个一个等，速度快很多
- **链式请求**：前一个请求的结果作为下一个请求的输入，像接力赛一样
- **jq 风格转换**：一种数据格式转换工具，能把复杂的数据结构"修剪"成你想要的样子
- **鉴权模板**：预设好的身份验证信息，调用外部 API 时自动带上"通行证"
- **速率限制**：控制发请求的速度，别把对方服务器打挂了

---

### Pipeline 流水线引擎（核心）

**一句话说清楚**：整个系统的"总指挥"，按照菜谱（场景配置）自动编排整个分析流程。

**举个例子**：AI Agent 说"帮我做一次竞品分析"。Pipeline 引擎接到指令后，自动执行：第一步从数据库拉竞品数据 → 第二步清洗和计算指标 → 第三步画对比图表 → 第四步生成 PDF 报告 → 返回结果。整个过程全自动，AI 只需要等最终结果。

**涉及的专业术语**：
- **Pipeline（流水线/管道）**：把多个步骤串成一条线，前一步的输出是后一步的输入
- **场景配置（Scenario）**：一份"菜谱"，描述了某个分析场景需要什么数据、怎么处理、输出什么
- **PipelineContext（流水线上下文）**：流水线的"记事本"，记录每一步的中间结果，方便下一步使用
- **条件分支**：根据中间结果决定走哪条路，比如"如果数据为空就跳过画图步骤"
- **skip/abort**：skip 是跳过当前步骤继续执行，abort 是直接终止整个流程

---

### 连接器层（Connector Layer）

**一句话说清楚**：系统伸向外部世界的"手"，负责从各种地方把数据拿回来。

**举个例子**：做竞品分析需要数据，数据可能在公司自己的数据库里，也可能在外部网站的 API 里，还可能是用户上传的一个文件。连接器就像不同的"采购渠道"——数据库连接器去仓库拿货，API 连接器去网店下单，文件连接器接收快递包裹。但不管从哪拿的，最后都统一装进同样的盒子（DataFrame）送进后厨。

**涉及的专业术语**：
- **DataFrame**：一种标准的表格数据结构，就像一张 Excel 表格，所有连接器都输出这个格式
- **REST API**：一种常见的网络接口标准，就像大家都用同一种格式的快递单
- **注册表模式**：新增一种连接器时，只需要"登记注册"一下就能用，不用改动已有代码
- **环境变量**：把密码、密钥等敏感信息放在系统环境里，不写在代码中，更安全

---

### 输出组装器（Output Assembler）

**一句话说清楚**：把流水线加工好的数据，打包成各种格式的"成品"交出去。

**举个例子**：流水线处理完之后，输出组装器会根据需求把结果变成不同的样子：要图表就画图（chart），要表格就渲染表格（table），要完整报告就生成 HTML/PDF（report），要给 Agent 看的摘要就生成文字总结（summary）。就像一个包装车间，同样的产品可以装进不同的礼盒。

**涉及的专业术语**：
- **chart**：图表输出（柱状图、折线图等）
- **table**：表格输出（带格式的数据表）
- **report**：完整报告输出（HTML/PDF 格式的文档）
- **file**：文件输出（Excel、CSV 等原始文件）
- **summary**：文字摘要输出，专门为 AI Agent 设计的简洁文字总结

## 🗺️ 整体关系图（文字版）

```
AI Agent 提出分析需求
        ↓
   ┌─────────────┐
   │  场景配置加载  │ ← 读取 YAML "菜谱"
   └──────┬──────┘
          ↓
   ┌─────────────┐
   │  连接器获取数据 │ ← 从数据库 / API / 文件拿数据，统一变成 DataFrame
   └──────┬──────┘
          ↓
   ┌─────────────┐
   │  数据处理流水线 │ ← 清洗、统计、计算（一步步传递中间结果）
   └──────┬──────┘
          ↓
   ┌─────────────┐
   │  输出组装器   │ ← 画图表 / 做表格 / 生报告 / 写摘要
   └──────┬──────┘
          ↓
   统一格式返回给 AI Agent
```

**两种调用方式：**

- **模式 A（Pipeline 一键全流程）**：Agent 说"做竞品分析" → 系统自动跑完所有步骤 → 直接返回最终结果。适合"我只要结果"的场景。
- **模式 B（原子 API 自由组合）**：Agent 自己一步步调——先调数据接口拿数据 → 再调图表接口画图 → 再调文件接口导出。适合"我想自己控制流程"的场景。

## ❓ 常见问题

### Q1: 这个服务和 AI Agent 是什么关系？
A：AI Agent（hiagent）是"前台服务员"，负责理解用户需求、做决策。这个 Web 服务是"后厨"，负责干 Agent 不擅长的事——处理大量数据、画图表、生成文件。Agent 动动嘴（发请求），后厨跑断腿（执行任务）。

### Q2: 为什么要分"Pipeline 模式"和"原子 API 模式"？
A：就像去餐厅吃饭——Pipeline 模式是点套餐，下单后等着上菜就行，省心；原子 API 模式是单点，自己想吃什么点什么，灵活。简单的场景用套餐省事，复杂的场景用单点自由。

### Q3: 新增一种分析场景需要做什么？
A：只需要写一份新的 YAML"菜谱"——告诉系统从哪里拿数据、怎么处理、输出什么。后厨的设备（代码）完全不用改。这就是"配置驱动"的好处。

### Q4: 数据源都不一样，系统怎么统一处理？
A：靠连接器（Connector）。不管数据来自数据库、API 还是文件，连接器都把它变成统一格式的 DataFrame（一张标准表格）送进流水线。就像不管食材从哪买的，到了厨房都装进同样的碗里处理。

### Q5: 系统安全性怎么保证？
A：四道防线——API Key 认证（门禁卡）、文件沙箱（隔离房间）、SQL 注入防护（防坏人）、凭据不硬编码（密码不写在代码里）。

## 💡 关键要点速记

- **核心定位**：AI Agent 的"万能后厨"，专门处理数据处理、可视化、文件生成等"脏活累活"
- **核心设计**：流水线引擎 + 场景配置（YAML），新增场景只写菜谱不改代码
- **两种使用方式**：Pipeline 一键全流程（省心）+ 原子 API 自由组合（灵活）
- **四大功能模块**：数据处理、可视化渲染、文件文档、API 编排
- **统一数据格式**：所有连接器都输出 DataFrame，保证流水线各环节无缝衔接
- **开发分四期**：先搭基础 → 再造流水线 → 然后做文档报告 → 最后完善扩展
- **安全有保障**：API Key 认证 + 文件沙箱 + SQL 注入防护 + 凭据外部化
