# 解读需求文档

## 使用场景

当用户阅读需求文档后感到困惑，希望用更简单直白的方式理解文档内容时，使用此技能。目标受众包括非技术人员、产品新人或任何需要快速理解需求全貌的人。

## 工作流程

### 第一步：获取需求文档

1. 确认用户指定的需求文档路径
2. 如果用户未指定，查找 `docs/` 目录下最新的需求文档
3. 通读全文，标记所有专业术语、技术概念和复杂逻辑

### 第二步：生成解读文档

使用以下模板结构生成解读文档，文档使用中文：

### 第三步：输出与保存

1. 将解读文档保存为 Markdown 文件
2. 默认保存路径：项目根目录下的 `docs/` 文件夹
3. 文件命名格式：`{时间戳}_{原文档主题}_需求解读.md`（遵循项目文件命名规范）
4. 如果 `docs/` 目录不存在，自动创建

## 解读原则

- **大白话优先**：所有解释必须使用日常口语，禁止照搬原文术语
- **类比要贴切**：生活类比必须是读者熟悉的场景（餐厅、快递、超市等）
- **故事化表达**：背景部分要像讲故事一样有起承转合，而非干巴巴的陈述
- **举例要具体**：每个功能模块必须附带一个具体的使用场景例子
- **术语速查表是核心**：确保文档中出现的每一个专业术语都被收录并解释
- **不遗漏关键信息**：虽然语言通俗，但不能省略原文档的核心需求和设计逻辑
- **适度幽默**：在不影响准确性的前提下，语言风格可以轻松活泼

## 注意事项

- 解读文档应与原文档内容一一对应，不能凭空添加原文档没有的功能
- 如果原文档存在歧义或矛盾，在解读中标注出来而非自行推断
- 术语速查表应覆盖原文档中 **所有** 出现的专业术语和技术名词
- 生活类比应选择跨文化通用的场景，避免过于地域化的比喻
- 对于无法用简单类比解释的复杂概念，分步骤拆解说明
